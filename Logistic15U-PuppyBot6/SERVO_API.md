# Servo commands — 0.1.14-dev

ใช้ header หลัก `#include <Logistic15U_PuppyBot6.h>` ตามเดิม ช่องคำสั่งเป็น **0–5** ตามซอร์สเดิม ไม่ใช่หมายเลขพอร์ตที่ตรวจจากสายจริง

`puppybot_setup()` เรียก `setupServos()` ให้แล้ว เริ่ม PWM โดยระดับสัญญาณของทั้ง 6 ช่องเป็นศูนย์ ไม่มีการสั่งมุมเริ่มต้น เมื่อต้องการเคลื่อนจึงเรียก `servoRun()` การเรียก `setupServos()` ซ้ำไม่ล้างคำสั่งช่องที่กำลังทำงาน ใช้คำสั่ง Servo บน core เดียวกัน เช่น core 0

| คำสั่ง | ผล |
| --- | --- |
| `servoRun(channel, angle)` | สั่งมุม 0–180 และเก็บมุมที่สั่งล่าสุดเฉพาะช่องนั้น |
| `servoStop(channel)` | หยุดพัลส์เฉพาะช่องที่เลือก ไม่หยุดอีกช่องที่ใช้ PWM slice เดียวกัน |
| `getServoLastAngle(channel)` | คืนมุมที่สั่งล่าสุด หรือ -1 ถ้ายังไม่เคยสั่ง/ช่องไม่ถูกต้อง/เปลี่ยนช่วงพัลส์ |
| `isServoActive(channel)` | true เมื่อมีคำสั่งส่งพัลส์อยู่ ไม่ใช่ผลวัดว่า Servo เคลื่อนสำเร็จ |
| `setServoPulseRange(channel, minimumUs, maximumUs)` | ตั้งช่วงพัลส์จากข้อมูลที่สอบเทียบจริง แยกรายช่อง เรียกได้เฉพาะเมื่อช่องนั้นหยุดพัลส์แล้ว |
| `control_servo(channel, startAngle, targetAngle, delayMs)` | เคลื่อนเป็นขั้นละ 1 องศาตามมุมเริ่มและมุมปลายทางที่ผู้เรียกระบุ |
| `servoSweep(channel, startAngle, endAngle, step, delayMs)` | เคลื่อนตามขนาด step ที่ระบุ ส่งถึงมุมปลายทางแม้ช่วงหารด้วย step ไม่ลงตัว |

คำสั่งตั้งค่า/สั่งงานคืน `bool`: true เมื่อรับคำสั่งได้, false เมื่อค่าผิดหรือเตรียม PWM ไม่สำเร็จ โค้ดเดิมที่ไม่ได้รับค่าคืนยังเรียกได้ตามเดิม ช่องนอก 0–5, มุมนอก 0–180, step <= 0 หรือ delayMs < 0 ถูกปฏิเสธก่อนขยับ ไม่ clamp ให้เอง และ **มุม -1 ไม่ใช่คำสั่งหยุด** ให้ใช้ `servoStop()`

ตัวอย่างรูปแบบเรียก โดยตัวแปรมุมและช่วงพัลส์ต้องมาจากข้อมูลของหุ่นจริง:

```cpp
servoStop(channel);
setServoPulseRange(channel, measuredMinUs, measuredMaxUs);
servoRun(channel, calibratedAngle);

int lastCommand = getServoLastAngle(channel);
servoStop(channel);
```

`servoStop()` ตั้ง compare ของช่องนั้นเป็นศูนย์ สัญญาณหยุดเมื่อ PWM ขึ้นรอบใหม่ จึงอาจเหลือพัลส์ปัจจุบันจนจบรอบ ไม่ปิดไฟเลี้ยง Servo และไม่รับประกันว่ากลไกยังค้างตำแหน่งเดิม หลังหยุดยังเก็บมุมที่สั่งล่าสุดไว้เป็นประวัติ เรียก `servoRun()` อีกครั้งจะเริ่มส่งพัลส์ แม้สั่งมุมเดิม

`control_servo()` และ `servoSweep()` ใช้มุมเริ่มที่ระบุในอาร์กิวเมนต์ ไม่เดาจากตำแหน่งจริงหรือจากช่องอื่น และยังเป็นคำสั่ง blocking บน core ที่เรียก โดย delay อยู่ระหว่างแต่ละขั้น การคืน true หมายถึงส่งคำสั่งสุดท้ายแล้ว ไม่ใช่การวัดว่าเพลาหรือชุดยกเดินทางถึงแล้ว ไม่ใช้ตัวแปรมุมรวม `current_degree_servo` อีกต่อไป

## PWM และค่าที่ต้องสอบเทียบ

ใช้ clock ของบอร์ดจริงคำนวณ divider และ TOP สำหรับ 50 Hz ที่ค่าบอร์ด 150 MHz ได้ divider 150, TOP 19999 และ 1 tick = 1 µs ถ้าเปลี่ยนค่าความถี่ตอน build จะคำนวณใหม่เมื่อเริ่มบอร์ด ไม่รองรับการเปลี่ยน clock ระหว่างกำลังใช้งาน Servo

ค่าเริ่มต้นยังอ้างการแมป **300–3000 µs** จากซอร์สเดิม ไม่ใช่การรับรองช่วงปลอดภัยของ Servo หรือกลไก ไม่เติมมุมยกต่ำ/สูง ค่า 90 ในการแมปเริ่มต้นให้ 1650 µs หลังแก้ clock เทียบกับประมาณ 1375 µs ในรุ่นก่อน ดังนั้นต้องทวนค่าที่เคยทดลองกับพัลส์รุ่นเก่าก่อนนำไปใช้

`setServoPulseRange()` ตรวจเพียง `0 < minimumUs < maximumUs < 20000` เพื่อไม่ให้พัลส์กินทั้งคาบ เงื่อนไขนี้ไม่ยืนยันว่ากลไกรับช่วงนั้นได้ ต้องใช้ข้อมูล Servo/ผลสอบเทียบจริง ตั้งค่าใน RAM เท่านั้น ไม่ Save ลง Flash เมื่อเปลี่ยนช่วงพัลส์ มุมที่สั่งล่าสุดจะกลับเป็น -1 เพราะการแมปเดิมใช้ไม่ได้แล้ว

การทดสอบซอฟต์แวร์ครอบคลุมเวลา PWM, การหยุดแยกช่อง, การเริ่มซ้ำ, มุมปลายทาง, step ผิดและค่าติดลบ ยังไม่ได้อัปโหลดหรือวัดพัลส์บนบอร์ดจริง ไม่มีการแก้ IMU หรือ Encoder
