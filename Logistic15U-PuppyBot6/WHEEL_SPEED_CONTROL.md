# Encoder speed feedback for line PD

รุ่น 0.1.22-dev เพิ่ม [หน้าดูค่าและตัวกรอง PD](LINE_PD_MONITOR.md) ส่วน PI ความเร็วล้อและข้อมูล Encoder ใช้เหมือนรุ่น 0.1.21-dev

PD ตามเส้นกำหนดคำสั่งเป้าหมายของ M1/M2 แยกกัน จากนั้น PI ของล้อแต่ละข้างใช้ความเร็วจาก Encoder ของตัวเองมาชดเชย PWM ไม่บังคับให้ค่าพัลส์สองข้างเท่ากันขณะเลี้ยว ผู้ใช้ยืนยันแล้วว่า Encoder 1 คู่ M1 และ Encoder 2 คู่ M2; ขาและไดรเวอร์ใช้ชุดเดิม ไม่มีค่า CPR/PPR เส้นผ่านศูนย์กลางล้อ หรืออัตราทดที่เดาเพิ่ม

## ข้อมูลที่ยังต้องวัด

ตั้งใน `RobotSetup::wheelSpeedSettings()` ของสเก็ตช์ผู้ใช้:

| ค่าแต่ละมอเตอร์ | ความหมาย |
|---|---|
| `encoder` | M1 ใช้ 1, M2 ใช้ 2 ตามที่ยืนยัน |
| `encoderSign` | +1 เมื่อคำสั่งมอเตอร์บวกทำให้พัลส์เพิ่ม, -1 เมื่อพัลส์ลด; 0 คือยังไม่ยืนยัน |
| `referencePwm` | คำสั่ง PWM เปอร์เซ็นต์ที่ใช้อ้างอิง เช่น 30 ที่สเก็ตช์ปัจจุบันใช้ |
| `referenceTicksPerSecond` | ขนาดอัตราพัลส์ที่วัดจริง ณ ความเร็วอ้างอิงนั้น ต้องเป็นบวก; 0 คือยังไม่มีข้อมูล |
| `kp`, `ki` | ค่าจูน PI ความเร็วล้อ ภายใน Lib เริ่มที่ 0.20 และ 0.50 ต่อวินาที เป็นค่าทดลอง ไม่ใช่ผลจูนจริง |

เมื่อข้อมูลทิศ/อัตราพัลส์ยังไม่ครบ `beginWheelSpeedControl()` จะไม่เปิด feedback และจอในคำสั่งวิ่งปัจจุบันจะแสดง **LINE PD ONLY / ENCODER NOT SET** เพื่อบอกว่ายังใช้ PD เดิม หลังใส่ข้อมูลจริงครบแล้ว คำสั่งเดิมจะเลือกโหมด **ENCODER + LINE PD** อัตโนมัติตั้งแต่เริ่มเที่ยว ไม่ได้ Save การตั้งค่าความเร็วนี้ลง Flash; แก้ใน RobotSetup.h แล้วคอมไพล์/อัปโหลด

## ตัวอย่างวัดโดยไม่เดาจำนวนพัลส์

เปิด File → Examples → Logistic15U-PuppyBot6 → **WheelSpeedMeasure** เป็นสเก็ตช์ทดสอบแยก ต้องยกล้อขับทั้งสองพ้นพื้นก่อนเริ่ม กด SW1 แล้วปล่อยเพื่ออนุญาตแต่ละการทดสอบ มันสั่งทีละมอเตอร์ที่ +30%, รอเริ่มหมุน 250 ms แล้วเก็บจำนวนพัลส์พร้อมเวลาจริงประมาณ 1000 ms จากนั้นหยุดเอง กด SW1 ระหว่างวิ่งเพื่อยกเลิกได้ จอและ Serial แสดงทิศพัลส์กับ ticks/s แยกสองตัว ไม่มีพัลส์จะไม่สร้างค่าอ้างอิงขึ้นเอง

ตัวอย่างนี้วัด **ไม่บรรทุกโหลด** เพื่อเริ่มตรวจ Encoder และทิศทาง ไม่ยืนยันความเร็วบนสนามจริง ต้องตรวจ/ปรับความเร็วเป้าหมายและจูนเมื่อวางพื้น/บรรทุกพัสดุ การทดสอบไม่เริ่ม IMU และไม่เปลี่ยนโค้ด IMU ในสเก็ตช์งานหลัก หลังทดสอบให้นำค่าไปกรอก RobotSetup.h และอัปโหลดสเก็ตช์หลักกลับ

หน่วยเป็น raw ticks/s ตามวิธีนับของไดรเวอร์เดิม ไม่ใช้ค่าจากสเปกมอเตอร์มาแทนโดยไม่ตรวจโหมดนับ หาก Encoder สองตัวมีความละเอียดหรือขนาดล้อต่างกัน อัตราพัลส์ที่ทำให้เคลื่อนตรงอาจต่างกัน ต้องเลือกค่าอ้างอิงแต่ละล้อตามของจริง ไม่กำหนดให้เท่ากันเพียงเพราะเป็นรถ 2WD

## การทำงาน

คำสั่งเปอร์เซ็นต์ `u` ของแต่ละล้อแปลงเป็น `targetTicks/s = u / referencePwm × referenceTicksPerSecond` เป็นความสัมพันธ์สัดส่วนสำหรับกำหนดเป้าหมาย ไม่ใช่ข้ออ้างว่าความเร็วจริงแปรตาม PWM อย่างสมบูรณ์ในทุกโหลด PWM อ้างอิงใช้เป็น feedforward และ PI แก้ผลต่างจากความเร็วที่วัดได้ การอ่านใช้ผลต่าง counter/เวลาจริง โดยปรับทิศตาม encoderSign

PI ป้องกัน integral สะสมเมื่อ output ติดเพดาน ล้างประวัติตอนหยุด/กลับทิศ จำกัด PWM ที่ ±100 หรือต่ำกว่าตาม pwmLimit และไม่ใช้การกลับทิศ PWM เพียงเพื่อเบรกเมื่อเป้าหมายยังเป็นบวก การอ่าน counter ไม่รีเซ็ต Encoder จึงไม่กระทบการนับระยะของผู้ใช้

รอบควบคุมเริ่มที่อย่างน้อย 20 ms และใช้ dt จริงสำหรับความเร็ว/PI; D ของเส้นปรับตาม dt เทียบกับคาบนี้ ค่า Kp/Kd ตามเส้นที่เคยจูนกับ Run_PID เดิม **ต้องตรวจและจูนใหม่เมื่อเปิดโหมด Encoder** เพราะคาบต่างกัน การเริ่มช่วงแรกและเปลี่ยน Front/Back ไม่เอา error เก่ามาสร้าง D kick

## API

```cpp
bool ready = beginWheelSpeedControl(settings); // ไม่มีการสั่งวิ่ง; ตั้งค่าและอ่าน baseline
bool ok = Run_PID_Encoder(speed, lineKp, lineKd);   // Front, เรียกซ้ำในลูป
// หรือ Run_PID_B_Encoder(speed, lineKp, lineKd);    // Back, ถอยตามแผงหลัง
stopWheelSpeedControl();

// ตามเส้นจนค่าเฉลี่ยพัลส์ 2 ล้อครบ targetPulses แล้วหยุด (blocking)
bool done = Run_PID_Pulses(speed, lineKp, lineKd, targetPulses, timeoutMs, rampMs); // ค่าเริ่มต้น 10000, 300
// หรือ Run_PID_B_Pulses(...) ใช้แผงหลัง
```

`Run_PID_Pulses`/`Run_PID_B_Pulses` เลือกโหมดครั้งเดียวต่อเที่ยว: ตั้ง settings ครบใช้ Encoder + line PD ไม่ครบใช้ `Run_PID`/`Run_PID_B` เดิม นับระยะจากค่าเฉลี่ยค่าสัมบูรณ์ของผลต่าง Encoder 1 และ 2 นับจากตอนเริ่มคำสั่ง ไม่รีเซ็ต counter คืน `true` เมื่อครบพัลส์ และคืน `false` เมื่อค่าไม่ถูกต้อง หมดเวลา หรือ Encoder fault ทุกกรณีมอเตอร์หยุดแล้ว

`restartWheelSpeedControl()` เริ่มเที่ยวใหม่ด้วย settings เดิมและ baseline ใหม่โดยไม่รีเซ็ต counter; `isWheelSpeedControlConfigured()` ตรวจ settings ครบ; `isWheelSpeedControlReady()` ตรวจพร้อมทำงานและไม่มี fault; `getWheelSpeedTelemetry()` คืน targetTicksPerSecond/ticksPerSecond/pwm/integral/count แยก M1/M2 พร้อมสถานะและเวลารอบจริง

`updateWheelSpeedControl(commandM1, commandM2)` ใช้เฉพาะ PI ล้อโดยไม่ตามเส้นได้ เรียกซ้ำถี่กว่าคาบที่ตั้งไว้ การใช้ API เหล่านี้เป็นของ core 0 ที่เป็นเจ้าของมอเตอร์และ Encoder ส่วน IMU/RGB ทำงาน core 1 เดิม เมื่อเปิด `beginLinePDMonitor()` คำสั่งตามเส้นจะบริการ TFT ครั้งละหนึ่งอักขระ หลีกเลี่ยงการวาดเต็มจอหรือเขียน Flash ระหว่างขับ หยุดตัวควบคุมก่อนเรียก motor()/ao()/คำสั่ง IMU-drive ชุดอื่น หรือรีเซ็ต Encoder แล้ว restart ก่อนใช้ feedback ต่อ

## การหยุดและ fault

- คำสั่ง Front-until-cross ของสเก็ตช์เลือกโหมดครั้งเดียวก่อนวิ่ง เจอแยก/หมดเวลา/Encoder fault จะหยุดทั้งสองมอเตอร์ หาก fault ระหว่างใช้ Encoder จะไม่เปลี่ยนเป็น PD เดิมแล้ววิ่งต่อ
- feedback ขาดช่วงเกิน 250 ms จะหยุด ต้องเริ่มใหม่อย่างชัดเจน
- มีพัลส์สวนทิศเป้าหมายหลังช่วงเผื่อกลับทิศ 250 ms จะหยุด ค่านี้เป็นนโยบายซอฟต์แวร์ที่ปรับได้ ไม่ใช่เวลาที่วัดจากกลไกจริง
- ไม่มีพัลส์จะหยุดเมื่อเกินเวลามากกว่าระหว่าง stallTimeoutMs (เริ่มที่ 1000 ms) กับสามช่วงพัลส์ที่คาดจากเป้าหมาย (จำกัดช่วงคำนวณที่ 60 s) เพื่อไม่ตัดสิน stall เร็วเกินไปที่เป้าหมายต่ำ คำสั่งวิ่งหลักยังมีเวลารวม 10 วินาทีตามสเก็ตช์
- API Encoder โดยตรงจะไม่ใช้ PD เดิมแทนเมื่อ config ไม่พร้อม ส่วน fallback เป็นนโยบายที่แสดงชัดใน RobotActions.h ของผู้ใช้เท่านั้น

Encoder ตรวจการหมุน ไม่ยืนยันการเคลื่อนจริงเมื่อยางลื่น และแก้ข้อมูลเซนเซอร์เส้นที่ผิดไม่ได้ ต้องทดสอบทิศเลี้ยว/ความเร็ว/โหลดจริงก่อนสรุปความนิ่ง
