# หน้าสถานะ IMU ตอนเปิดเครื่อง — 0.1.18-dev

ใน setup() เรียก `waitIMUCalibration()` หลัง `puppybot_setup()` และ `rgbBoardReady.store(true, ...)` ก่อนสั่ง Servo/มอเตอร์หรือเข้า `wait_SW1()` ฟังก์ชันนี้วาด TFT บน core 0 ส่วน initIMU/การอ่านเซนเซอร์ยังอยู่ core 1 ตามเดิม ไม่มีการอ่าน I2C ข้าม core เพื่อวาดหน้าจอ

| ข้อความบนจอ | ความหมาย / การทำงาน |
| --- | --- |
| WAITING FOR IMU / CONNECTING | รอ core 1 / เริ่ม IMU และ DMP |
| CALIBRATING IMU | ตั้งค่าอ้างอิง Yaw 300 รอบ แสดงเวลาที่ผ่านไปและเปอร์เซ็นต์รอบที่เสร็จ วางหุ่นให้นิ่ง |
| IMU READY | จบรอบและได้รับข้อมูลล่าสุด แสดง 0.7 วินาทีแล้วไปต่อ |
| IMU NOT READY | เริ่มอุปกรณ์ไม่สำเร็จ อาจไม่ติดตั้ง สายผิด หรืออุปกรณ์มีปัญหา มีรหัส init error |
| NO IMU DATA | ไม่มีข้อมูลที่ใช้ได้ หรือข้อมูลล่าสุดเก่ากว่า 250 ms เมื่อจบรอบ |
| IMU TIMEOUT | สถานะยังไม่จบภายในเวลาที่กำหนด ค่าเริ่มต้น 15 วินาที |
| IMU DISABLED | ตั้งใจไม่ใช้ IMU แสดง 0.7 วินาทีแล้วไปต่อ |

เมื่อมีปัญหา จอค้างข้อความไว้ให้ตรวจสายและปิด–เปิดใหม่ หรือกดแล้วปล่อย SW1 เพื่อใช้ต่อโดยไม่มี IMU การกดนี้ยังไม่เลือก Start ในเมนู `wait_SW1()` ต้องเลือก Start แยกตามเดิม ปุ่มที่ค้างมาก่อนเข้าหน้าผิดพลาดจะไม่ถูกนับเป็นการยืนยัน

หากตั้งใจไม่ติดตั้ง IMU เปลี่ยนค่าที่ด้านบนของ .ino:

```cpp
constexpr bool USE_IMU = false; // true เมื่อติดตั้ง IMU
```

setup1() ยังคงเห็นคำสั่งเดิมโดยตรง:

```cpp
if (initIMU(USE_IMU)) {
  updateIMU_fine_offset_Yaw(300);
  offset_yaw_loop1 = getOffsetYaw();
}
beginRGB();
```

`initIMU(false)` ไม่สื่อสารกับ IMU ส่วน RGB เริ่มบัสของตัวเองตามเดิม ใน loop1() ใช้ `isIMUCalibrated()` แทน `isIMUReady()` เพื่อไม่อ่านมุมต่อเมื่อปิดใช้/คาริเบตล้มเหลว/timeout `isIMUReady()` เดิมหมายถึงตัวอุปกรณ์เริ่มสำเร็จเท่านั้น ฟังก์ชันใหม่ `getIMUStartupState()` อ่านสถานะผ่าน atomic ได้จากทั้งสอง core

`waitIMUCalibration()` คืน true เมื่อสำเร็จ และ false เมื่อปิด IMU หรือผู้ใช้ยืนยันข้ามข้อผิดพลาด ปรับเวลารอสูงสุดได้ เช่น `waitIMUCalibration(20000)` เป็น 20 วินาที นี่คือเวลาตรวจว่าขั้นตอนค้าง ไม่ใช่เวลาคาลิเบรต 3 วินาที และไม่ใช่ค่าที่สอบเทียบจากฮาร์ดแวร์

เวลาตั้งค่าอ้างอิงยังเป็น 300 × delay(10) = อย่างน้อย 3 วินาที บวกเวลาอ่านข้อมูล ไม่มีการเปลี่ยนสูตร quaternion/Yaw หรือเพิ่มเกณฑ์ความนิ่ง IMU READY หมายถึงมีข้อมูลล่าสุดและบันทึกค่าอ้างอิงแล้ว ไม่รับรองว่า gyro หยุด drift หรือหุ่นนิ่งสนิท เปอร์เซ็นต์คือรอบที่ทำเสร็จ ไม่ใช่ความแม่นยำ

สเก็ตช์เลื่อน lift_down() ไปหลังหน้าสถานะ เพื่อไม่ให้ Servo ขยับระหว่างตั้งค่า Yaw มุมและเวลาของ RobotActions.h ไม่เปลี่ยน เมื่อข้าม IMU ห้ามถือมุมค้าง/ศูนย์ในหน้าดูค่าเป็นมุมจริง และให้ใช้เงื่อนไข `isIMUCalibrated()` ก่อนเรียกงานที่ต้องพึ่ง IMU + PID

Timeout ทำให้จอและ core 0 ใช้งานต่อได้ แต่ไม่ได้ฆ่าคำสั่ง I2C ที่ค้างบน core 1 ถ้าบัสค้างจริง RGB ที่อยู่บน core 1 อาจยังไม่พร้อมด้วย ต้องแก้สายแล้วเปิดเครื่องใหม่ ความสำเร็จที่มาช้าหลัง timeout จะไม่เปลี่ยนสถานะกลับเป็น Ready ในรอบเปิดเครื่องนั้น

TFT ใช้ภาษาอังกฤษตามฟอนต์ที่มีใน Library จัดข้อความกึ่งกลาง ล้างทั้งจอเฉพาะตอนเข้าหน้านี้ครั้งแรกหรือเปลี่ยนขนาด/แนวจอ เมื่อเปลี่ยนสถานะจะเขียนทับเฉพาะช่องตัวอักษรที่ข้อความหรือสีเปลี่ยน โดยใส่พื้นหลังไปพร้อมตัวอักษร ไม่ล้างแถวให้ว่างก่อน แถบความคืบหน้าวาดเฉพาะส่วนที่เพิ่ม/ลด หรือเปลี่ยนสี ส่วนหัว กรอบ และข้อความที่ไม่เปลี่ยนไม่วาดซ้ำ

## เสียงแจ้งผล IMU

`waitIMUCalibration()` ส่งเสียงอัตโนมัติ ไม่ต้องเพิ่มคำสั่งใน .ino:

- IMU READY: เสียงสูง 2400 Hz นาน 180 ms หนึ่งครั้ง
- IMU NOT READY / NO IMU DATA / IMU TIMEOUT: เสียงต่ำ 440 Hz นาน 600 ms หนึ่งครั้ง ไม่ดังวนขณะค้างหน้าปัญหา
- USE_IMU=false: ไม่มีเสียงแจ้งผล IMU เพราะเป็นการปิดใช้งานโดยตั้งใจ เสียงเปิดบอร์ดเดิมยังมีตามปกติ

ใช้ขา Buzzer เดิมของ Lib และ tone() แบบไม่รอจนจบเสียง จอและ SW1 ยังทำงานระหว่างเสียงเตือน หากกด SW1 ข้ามก่อนเสียงจบจะหยุดเสียงก่อนเข้าเมนู ใช้ noTone() ปิดเสียงเมื่อออกจากหน้าสถานะเพื่อไม่ให้ชนเสียงของเมนู/RGB
