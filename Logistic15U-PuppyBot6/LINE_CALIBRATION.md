# Calibrate Line — Mux 8 Front / Back

รุ่น 0.1.20-dev เพิ่มเมนู `6. Calibrate Line` ใน `wait_SW1()` ใช้การอ่าน Mux ชุดเดียวกับหน้าดู F0–F7 / B0–B7 เดิม ไม่เพิ่มหรือเปลี่ยนขาฮาร์ดแวร์ การสอบเทียบนี้เป็นของเซนเซอร์ตามเส้น ไม่เกี่ยวกับการสอบเทียบสี RGB

## วิธีใช้บนจอ

1. เปิดหุ่น รอสถานะ IMU ตามเดิม แล้วเลือก **Calibrate Line**
2. เลือก **Front** หรือ **Back** แต่ละแผงแสดง `Saved` หรือ `Not calibrated`
3. เลือก **All 8 channels** ถ้ามีวัสดุพื้น/เส้นกว้างพอให้ทั้งแผงอ่านพร้อมกัน หรือ **One by one** สำหรับเส้นแคบ
4. หน้าจอ **FLOOR**: วางช่องเป้าหมายเหนือพื้นสนาม รักษาความสูงเท่าตอนวิ่ง เลือก **Capture** และถือให้นิ่งจนเก็บเสร็จ
5. หน้าจอ **LINE**: วางช่องเป้าหมายเหนือวัสดุเส้น แล้ว Capture เช่นเดียวกัน อย่าเลื่อนผ่านพื้นและเส้นปนกันขณะเก็บตัวอย่าง
6. ตรวจตาราง **CH / Min / Max / Gap** เครื่องหมาย `+` สีเขียวคือผ่านการตรวจช่วงข้อมูล ส่วน `!` คือช่องที่ต้องเก็บใหม่
7. เลือก **Save** รอข้อความ `Saved on board` แล้วเลือก **Exit** กลับหน้าเลือกแผง เลือกอีกแผงเพื่อสอบเทียบ หรือเลือก Exit อีกครั้งกลับเมนูหลัก

**BOOT กดแล้วปล่อย = ถัดไป; SW1 กดแล้วปล่อย = เลือก** ขณะกำลังเก็บตัวอย่าง BOOT/SW1 ไม่มีผล เพื่อไม่ให้การกดซ้ำยกเลิกหรือเริ่มเก็บใหม่ เมนูใช้เสียงถัดไป/เลือกต่างกัน มีเสียงเมื่อเก็บครบหรือ Save สำเร็จ และเสียงต่ำเมื่อข้อมูลไม่ผ่านหรือ Save ล้มเหลว

แบบ One by one จะเรียง **FLOOR ช่อง 0–7 → LINE ช่อง 0–7** จอระบุช่องที่ต้องวาง แต่ละช่องต้องได้อ่านพื้นและเส้นจริง ห้ามถือว่าเส้นที่อยู่ใต้ช่องเดียวเป็นค่าของทั้งแผง

แต่ละ Capture เก็บ 16 ตัวอย่าง โดยเว้นรอบอ่านอย่างน้อย 10 ms เพื่อตรวจค่าเฉลี่ยและช่วงแกว่ง ใช้เลขนี้เป็นนโยบายการเก็บตัวอย่าง ไม่ใช่ค่าระยะติดตั้งหรือเกณฑ์แสงของฮาร์ดแวร์ที่ยืนยันแล้ว เวลาเก็บจริงรวมเวลาสแกน Mux และวาดจอด้วย

## Save / Retry / Exit

- **Save** บันทึกเฉพาะแผงที่เลือก ต้องเก็บครบทั้ง 8 ช่องและผ่านการตรวจทุกช่อง บันทึกสำเร็จจึงนำข้อมูลไปใช้กับการอ่านเส้น
- **Retry** เริ่มสอบเทียบพื้นและเส้นของแผงนั้นใหม่ ค่าที่เคย Save ยังอยู่
- **Exit** ทิ้งชุดสอบเทียบใหม่ที่ยังไม่ Save และกลับหน้าเลือกแผง โดยไม่เปลี่ยนค่าที่ใช้งานอยู่
- ขณะสอบเทียบมอเตอร์หยุด การเลือก Start ในเมนูหลักยังเป็นขั้นตอนเริ่มทำงานตามสเก็ตช์เดิม

การตรวจคุณภาพกำหนดให้ผลต่างค่าเฉลี่ยพื้น/เส้นมากกว่า `2 × (ช่วงแกว่งพื้น + ช่วงแกว่งเส้น + 1)` รวมทั้งตรวจจำนวนตัวอย่างและความสมเหตุสมผลของข้อมูล เลข 1 เผื่อความละเอียดจำนวนเต็มของ ADC กฎนี้เป็นตัวกรองข้อมูลเบื้องต้น ไม่ใช่หลักฐานยืนยันความแม่นยำบนสนาม ต้องลองกับแสง ความสูง และน้ำหนักบรรทุกจริง หากไม่ผ่านให้ตรวจการวางแต่ละช่องและแสงก่อน ไม่ลดเกณฑ์เพื่อบังคับให้ผ่าน

## การนำค่าไปใช้กับ RunPD

`wait_SW1()` โหลดค่าที่บันทึกไว้ให้อัตโนมัติทั้งสองแผง ไม่ต้องเพิ่มโค้ดสอบเทียบใน `.ino` เมื่อโหลดหรือ Save สำเร็จ จะตั้งแผงนั้นเป็น **Mux 8, logical channels 0–7** ตามเลขในหน้าดู Mux เดิม และใส่ช่วงแสงรายช่องให้ตัวอ่านเส้น

- พื้นถูกแปลงเป็น 0 และเส้นเป็น 100 ต่อช่อง รองรับทั้งกรณีค่าเส้นสูงหรือต่ำกว่าพื้น โดยไม่เดาขั้วสัญญาณ
- `readline()` / `readline_B()`, `Read_sumValue_sensor()` / `_B` และ `Read_status_sensor()` / `_B` ใช้การแปลงช่วงเดียวกัน `Read_status_sensor()` เป็น true เมื่อค่าความเป็นเส้นเกิน 50
- `Run_PID()` ใช้หน้า ส่วน `Run_PID_B()` ใช้หลังตามเดิม ยังไม่ได้เพิ่ม Ramp, เปลี่ยนสูตร P/D หรือเพิ่มระบบกู้เส้น/timeout ในรอบนี้
- เลขช่อง 0–7 เป็นเลขตาม Mux เดิม ไม่ได้ยืนยันว่าทิศซ้าย–ขวาของการติดตั้งตรงกับมอเตอร์ ต้องตรวจทิศการเลี้ยวบนหุ่นก่อนวิ่งจริง
- หากปรับ `analogReadResolution()`, เปลี่ยนแผง/การต่อช่อง หรือความสูงติดตั้ง ต้องสอบเทียบใหม่ ข้อมูลบันทึกระบุ Mux mapping revision และจำนวน 8 ช่อง ไม่ใช่การตรวจจับฮาร์ดแวร์อัตโนมัติ
- เมื่อไม่มีข้อมูลที่ใช้ได้ จะแสดง `Not calibrated` และไม่เอาข้อมูลเสียทับค่าที่ผู้ใช้ตั้งเอง เมนู Start ยังใช้ได้สำหรับงานอื่น จึงควรตรวจความพร้อมก่อนเรียกตามเส้น

สำหรับสเก็ตช์ที่ไม่ใช้ `wait_SW1()` สามารถโหลดเองหลัง `puppybot_setup()` บน core 0:

```cpp
bool frontReady = loadLineCalibration(LineSide::Front);
bool backReady  = loadLineCalibration(LineSide::Back);
```

`hasLineCalibration(LineSide::Front)` / `Back` ตรวจว่ามีชุดสอบเทียบที่โหลด/Save สำเร็จใน RAM หรือไม่ ไม่ได้ตรวจเซนเซอร์จริงหรือยืนยันการตั้งค่าที่ผู้ใช้แก้ภายหลัง อย่าเปลี่ยนโหมด/จำนวน/ลำดับช่องหรือ Min/Max หลังโหลดโดยไม่จัดค่าที่สัมพันธ์กันใหม่

## พื้นที่บันทึกและ IMU

ใช้ EEPROM emulation ของ Arduino-Pico ขนาด 4096 bytes: Front ที่ 3456–3595 และ Back ที่ 3616–3755 (ช่องสำรองแผงละ 160 bytes) แยกจาก RGB 3072–3399 แต่ละแผงมี magic, schema, side, channel count, mapping revision และ checksum ตรวจข้อมูลก่อนโหลด การบันทึกโหลดทั้ง sector และรักษาไบต์ส่วนอื่นไว้ ไม่ล้าง RGB

การเขียน Flash ใช้ `EEPROM.commit()` ของ core ซึ่งพักอีก core ชั่วคราวระหว่างเขียนแล้วปล่อยกลับตามกลไกเดิม ไม่เปลี่ยน init/update/offset ของ IMU, Encoder หรือ Servo การคงข้อมูลหลังดับไฟได้ทันทีระหว่าง Flash กำลังเขียนไม่รับประกัน เพราะ EEPROM emulation ใช้ sector ร่วมกัน

จอแสดง 1/2 FLOOR และ 2/2 LINE พร้อมความคืบหน้า 0/16; หน้า Min/Max แสดงค่าปลายช่วงต่ำ/สูงจากค่าเฉลี่ยพื้นและเส้น ไม่ได้สมมติว่าพื้นต้องเป็น Min เสมอ ข้อมูลที่เคย Save แบบ 32 ตัวอย่างยังโหลดได้ ไม่ต้องสอบเทียบใหม่เพราะการอัปเดตนี้เพียงอย่างเดียว

จอวาดเฉพาะแถวที่ข้อมูลหรือสถานะเปลี่ยน โดยแบ่งการล้างแถวและวาดข้อความเป็นคนละรอบ อ่านปุ่มระหว่างงานวาดแต่ละชิ้นและตรวจปุ่มทุกอย่างน้อย 5 ms เมื่อกลับเข้ารอบควบคุม (เวลาวาดแต่ละชิ้นขึ้นกับฮาร์ดแวร์จริง) ไม่มีการล้างทั้งจอซ้ำระหว่างอ่านค่า ตัวอักษรใช้ฟอนต์เดิมของ TFT และรองรับกรอบ 160×128 / 128×160
