# API ดูและปรับ PD ตามเส้นบน TFT

Library รุ่น 0.1.22-dev ใช้ตัวกรอง D และตัวจำกัดแรงเลี้ยวร่วมกันใน `Run_PID`, `Run_PID_B`, `Run_PID_Encoder` และ `Run_PID_B_Encoder` การควบคุม PI ความเร็วล้อและการอ่าน IMU ใช้โค้ดเดิม

## หน้าดูค่า

`beginLinePDMonitor(speed, kp, kd, side)` เปิดหน้า TFT หลังออกจาก `wait_SW1()` และก่อนเริ่มวิ่ง `side` เริ่มที่ `LineSide::Front` หรือเลือก `LineSide::Back` ได้ ฟังก์ชันคืน `false` เมื่อพารามิเตอร์ผิดหรือกำลังควบคุมการวิ่งอยู่ เพื่อไม่ล้างทั้งจอระหว่างวิ่ง

`updateLinePDMonitor()` อัปเดตข้อมูลทุก 100 ms และวาดครั้งละหนึ่งอักขระขนาด 6×8 เฉพาะส่วนที่เปลี่ยน ล้างทั้งจอครั้งเดียวเมื่อเปิดหน้า ฟังก์ชัน PD ทั้งสี่ตัวเรียกส่วนอัปเดตนี้ให้เองเมื่อเปิดหน้าดูค่า จึงใช้กับคำสั่งตามเส้นแบบรอจนเจอแยกได้ ส่วนการดูค่าขณะหยุดต้องเรียกใน `loop()`

| ช่องบน TFT | ความหมาย |
|---|---|
| `Pos` และแถบตำแหน่ง | ตำแหน่งเส้นจาก Mux 8 ช่อง ช่วง 0–700 กลาง 350 |
| `Err` | Position ลบ 350 |
| `P`, `D` | ผลของ P และ D หลังกรอง ก่อนจำกัดผลรวม หน่วยจุดเปอร์เซ็นต์คำสั่งมอเตอร์ |
| `Turn` และ `LIMIT` | ผลรวม P+D ที่จำกัดแล้ว พร้อมธงเมื่อชนเพดานแรงเลี้ยวหรือคำสั่งมอเตอร์ |
| `M1`, `M2`, `TARGET`, `ACT` | อัตราพัลส์เป้าหมายและที่วัดจริงแยกล้อ หน่วย ticks/s ไม่ใช่ RPM |
| `PWM1`, `PWM2` | คำสั่ง PWM ล่าสุดจากตัวควบคุม ไม่ใช่ค่าที่วัดจากขามอเตอร์ |
| `dE`, `F` | การเปลี่ยน error ที่ปรับตามเวลา ก่อนกรองและหลังกรอง ยังไม่คูณ Kd |
| `dt`, `F`, `C` แถวล่าง | เวลารอบ PD จริง, เวลา filter และเพดาน correction ตามลำดับ หน่วยสองค่าแรกเป็น ms |
| สถานะแถวสุดท้าย | พบเส้น, ไม่พบเส้น, ต้องสอบเทียบ หรือเหตุขัดข้อง Encoder |

ตัวเลขยาวเกินช่องแสดง `RANGE` แทนการล้นจอ ค่าไม่พร้อมแสดง `--` หน้ารองรับ TFT 160×128 และ 128×160

## PREVIEW และค่าจากการวิ่งจริง

`PREVIEW - NO DRIVE` อ่านเส้นจากค่า Calibrate ที่ Save แล้ว และคำนวณ P/D สำหรับดูผลเท่านั้น ไม่สั่งมอเตอร์ เป้าหมายล้อเป็นศูนย์ อ่านความเร็วจริงจาก Encoder เมื่อมีเครื่องหมายพัลส์ที่ยืนยันแล้ว รอบแรกยังไม่มีผลต่างเวลาจึงแสดง `--`

PREVIEW ใช้ประวัติ D แยกจากวงควบคุมจริง ไม่รีเซ็ต Encoder และไม่เขียนค่าทับประวัติ PD ที่ใช้ขับ ถ้าไม่มี Calibrate ของแผงที่เลือกจะแสดง `LINE CAL REQUIRED` การขยับหุ่นด้วยมือช่วยตรวจตำแหน่งและทิศทาง แต่ยังไม่ยืนยันค่าจูนเมื่อวิ่งจริง

เมื่อเรียก `Run_PID_Encoder` หรือ `Run_PID_B_Encoder` หน้าจะเปลี่ยนเป็น `RUN / ENCODER + PD` ใช้ค่า P/D และ TARGET/ACT จากตัวควบคุมที่สั่งมอเตอร์จริง หน้าดูค่าไม่อ่านเส้นซ้ำระหว่างวงควบคุมทำงาน เมื่อหยุดผ่าน `stopWheelSpeedControl()` จอจะกลับ PREVIEW พร้อมเป้าหมายศูนย์ หากเกิด fault จะแสดง `STOP / PREVIEW` และเหตุขัดข้อง

`RUN / LEGACY PD` ใช้ค่า PD จริงจาก `Run_PID` หรือ `Run_PID_B` โดยไม่มี PI ความเร็วล้อ จึงแสดง TARGET เป็น `--` และแสดงคำสั่ง PWM กับอัตราพัลส์ที่อ่านได้ ถ้าใช้ `updateWheelSpeedControl()` โดยไม่ตามเส้น จอแสดง `WHEEL PI / PREVIEW` เพื่อแยก P/D ทดลองจาก PI ที่กำลังขับ

ข้อมูล PD ที่ไม่อัปเดตเกิน 250 ms จะกลับ PREVIEW ข้อความ PREVIEW ระบุแหล่งข้อมูล PD ไม่ใช่คำสั่งหยุดมอเตอร์ คำสั่งหยุดของโหมด Encoder คือ `stopWheelSpeedControl()`

## ตัวเลือกการกรองและจำกัดแรงเลี้ยว

`getLinePDOptions()` คืนค่าปัจจุบัน `setLinePDOptions(options)` ตรวจค่าก่อนตั้งและล้างประวัติ D แต่ไม่สั่งหยุดมอเตอร์ ต้องตั้งก่อนเริ่มช่วงวิ่ง ค่าเหล่านี้อยู่ใน RAM ไม่ Save ลง Flash

| ตัวเลือก | เริ่มต้น | ช่วงและผล |
|---|---:|---|
| `derivativeFilterMs` | 60 | 0–2000 ms; 0 ปิด filter ค่าสูงขึ้นลดการเปลี่ยนเร็วของ D แต่เพิ่มความหน่วง |
| `maxCorrection` | 20 | 0–100 จุดเปอร์เซ็นต์ จำกัดผลรวม P+D ทั้งสองทิศ |
| `allowWheelReverse` | false | ลดเพดาน correction เพิ่มตามขนาด speed เพื่อไม่ให้ล้อกลับทิศเพราะ PD; true อนุญาตให้กลับทิศ |

ตัวอย่างการตั้งค่าก่อน `beginLinePDMonitor()`:

```cpp
LinePDOptions pd;
pd.derivativeFilterMs = 60;
pd.maxCorrection = 20;
setLinePDOptions(pd);
```

60 ms และ 20 เป็นค่าเริ่มทดลองของซอฟต์แวร์ ไม่ใช่ผลจูนหุ่นจริง ที่ speed 30 และ correction 20 คำสั่งก่อน PI อยู่ที่ 10 และ 50 เปอร์เซ็นต์ตามทิศเลี้ยว เมื่อคำสั่งล้อข้างหนึ่งเกิน 100 จะลดคำสั่งทั้งคู่ตามสัดส่วนเพื่อเก็บทิศเลี้ยวไว้ ค่า PWM จริงยังผ่าน PI และเพดาน PWM ของแต่ละล้อ

สูตร D ใช้ `raw = (error - previousError) × nominalMs / dtMs` แล้วกรองด้วย `filtered += alpha × (raw - filtered)` โดย `alpha = dtMs / (derivativeFilterMs + dtMs)` ก่อนคูณ Kd โหมด Encoder ใช้ nominalMs ตาม `samplePeriodMs` เริ่มที่ 20 ms ส่วน Legacy ใช้ 20 ms รอบแรกหลัง reset ไม่มี D kick ค่า Kp/Kd เดิมจึงต้องตรวจและจูนใหม่ โดยเฉพาะ Legacy ที่เดิมไม่ได้ปรับ D ตามเวลา

`resetLinePD()` ล้างประวัติ PD และยกเลิกสถานะกำลังตามเส้น ไม่รีเซ็ต Encoder `ao()` เรียก reset นี้ด้วย โหมด Encoder ต้องหยุดตัวควบคุมผ่าน `stopWheelSpeedControl()` ก่อนสลับไปใช้คำสั่งขับอื่น

## ข้อมูลสำหรับโค้ดผู้ใช้

`getLinePDTelemetry()` คืนข้อมูลวงควบคุมล่าสุด เช่น `position`, `pTerm`, `dTerm`, `correction`, `command1`, `command2`, `running`, `source` และ `limited` ค่าเริ่มต้นเป็น `valid=false`

`getLinePDMonitorReading()` คืนข้อมูลที่เตรียมสำหรับจอรอบล่าสุด พร้อม `preview`, `target1`, `target2`, `actual1`, `actual2` และธงความพร้อมของค่า `isLinePDMonitorActive()` ตรวจว่าเปิดหน้าอยู่ `endLinePDMonitor()` ปิดการอัปเดตโดยไม่เปลี่ยนคำสั่งมอเตอร์

หน้าดูค่าและการขับใช้ core 0 เท่านั้น ต้องใช้ TFT หน้าเดียวในช่วงนี้ ถ้าจะกลับไปแสดง RGB ให้ปิด monitor ก่อน โค้ด IMU และ RGB ที่อ่านข้อมูลบน core 1 ใช้เหมือนเดิม การวาดหนึ่งอักขระยังใช้เวลา SPI รอบควบคุมใช้ dt จริงรองรับความแปรผันนี้ แต่ต้องตรวจความลื่นและความเร็วล้อบนบอร์ดจริง
