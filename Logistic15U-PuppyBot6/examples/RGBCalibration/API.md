# API สอบเทียบ RGB

Library รุ่นในเครื่อง `0.1.8-dev` มีข้อมูล 2 เซนเซอร์ × 6 สี สีใช้ `RGBColor::Red`, `Green`, `Blue`, `Yellow`, `White`, `Black` เซนเซอร์ใช้ `RGB0` หรือ `RGB1` ส่วน `RGBColor::Unknown` เป็นผลจากการแยกสีและไม่อนุญาตให้เก็บเป็นสีที่เจ็ด

| API | ผลลัพธ์ |
| --- | --- |
| `beginRGBCalibration()` | โหลด EEPROM และเริ่มหน้า TFT คืน `true` เมื่อพบข้อมูลถูกต้อง |
| `beginRGBCalibrationSW1()` | เริ่มเมนู SW1 หลังตั้งค่าบอร์ดและหน้า calibration ใช้ `swpin` เดิมกับ `INPUT_PULLUP` กดแล้ว LOW |
| `updateRGBCalibrationSW1()` | ตรวจปุ่มและเปลี่ยนเมนูโดยไม่รอ BOOT กดแล้วปล่อยเพื่อเลื่อน SW1 กดแล้วปล่อยเพื่อเลือก ใช้ debounce 30 ms และอ่านปุ่มทุกอย่างน้อย 20 ms |
| `selectRGBCalibration(RGB0, RGBColor::Red)` | เลือกเซนเซอร์และสีสำหรับดูบนจอ คืน `false` เมื่อกำลังเก็บหรือพารามิเตอร์ไม่ถูกต้อง |
| `startRGBCalibration(RGB0, RGBColor::Red, 20)` | เริ่มเก็บเฟรมใหม่ตามจำนวนที่ระบุ ค่าเริ่มต้น 20, ช่วง 1–1000 คืน `false` เมื่อกำลังเก็บหรือพารามิเตอร์ไม่ถูกต้อง |
| `updateRGBCalibration()` | ตรวจเฟรมใหม่ใน cache และสะสมตัวอย่าง ไม่มี I2C หรือการรอจนเก็บครบ |
| `showRGBCalibration()` | วาดค่าจาก cache และสถานะสอบเทียบ ไม่มี I2C วาดเต็มจอเมื่อเริ่มหรือขนาดจอเปลี่ยน จากนั้นวาดเฉพาะช่องที่เปลี่ยน |
| `cancelRGBCalibration()` | ยกเลิกชุดที่กำลังเก็บ ค่าชุดเดิมยังอยู่ |
| `getRGBCalibration(RGB1, RGBColor::Black)` | คืน `RGBColorReference` ของคู่เซนเซอร์กับสีที่ระบุ |
| `getRGBCalibrationState()` | คืนสถานะรวมแบบอ่านอย่างเดียว มี `channel()`, `color()`, `state()`, `count()`, `target()`, `completed(channel)`, `dirty()` และ `storage()` |
| `saveRGBCalibration()` | บันทึกชุดที่เก็บเสร็จทั้งหมดลง Flash คืน `false` เมื่อกำลังเก็บ ไม่มีสีที่เก็บแล้ว หรือ commit ล้มเหลว |
| `loadRGBCalibration()` | โหลดชุดที่บันทึกไว้ คืน `false` เมื่อกำลังเก็บ ข้อมูลไม่มี หรือ checksum/version ไม่ผ่าน ค่าที่อยู่ใน RAM ยังอยู่เมื่อโหลดล้มเหลว |
| `printRGBCalibration(Serial)` | ส่ง CSV ของคู่เซนเซอร์กับสีที่มีการวัดแล้ว แต่ละแถวมีจำนวนตัวอย่าง ค่าเฉลี่ย ต่ำสุด และสูงสุดของ RGBC |

`RGBColorReference` ประกอบด้วย `samples`, `mean`, `minimum`, `maximum` แต่ละกลุ่มค่ามี `red`, `green`, `blue`, `clear` เป็น `uint16_t` ทั้งหมดมาจาก raw ของเซนเซอร์ Clear ไม่ได้คำนวณจากผลรวม RGB และไม่ผ่านการ normalize ค่าเฉลี่ยปัดใกล้จำนวนเต็ม ไม่เก็บทุกเฟรมแยกไว้หลังจบชุด

`samples == 0` หมายถึงยังไม่มีข้อมูล RGB รวมเป็นศูนย์, Clear < 10 หรือช่องใด >= 21504 จะทำให้การเก็บจบด้วย InvalidSignal และคงค่าชุดเดิม ค่าใน UI สีและ swatch เป็นส่วนแสดงผล ไม่มีผลต่อชุดสอบเทียบ

การเก็บข้ามเฟรมที่อยู่ใน cache ก่อนเริ่ม และนับ `sequence` ของเฟรมใหม่เพียงครั้งเดียว การอ่าน RGB อีกเซนเซอร์ไม่เพิ่มจำนวนตัวอย่างของเซนเซอร์ที่เลือก ขาดเฟรมใหม่ 2000 ms หรืออ่านว่าเซนเซอร์หลุดแล้วการเก็บยุติ ชุดเดิมถูกแทนที่เมื่อได้ครบตามจำนวนเท่านั้น ค่า 20 ตัวอย่างและ 2000 ms เป็นการตั้งค่าการเก็บข้อมูล ไม่ใช่ threshold แยกสี

`RGBCaptureState` มี `Ready`, `Collecting`, `Captured`, `Cancelled`, `Offline`, `TimedOut`, `InvalidSignal` ส่วน `RGBStorageState` มี `RAM`, `Loaded`, `Saved`, `Invalid`, `Failed`

สถานะสอบเทียบ, TFT, Serial และ EEPROM ต้องใช้บน core เดียวกัน ตัวอย่างใช้ core 0 ส่วน `beginRGB()` และ `updateRGB()` อยู่ core 1 และส่งข้อมูลผ่าน cache ที่มี mutex

เมนูเริ่มที่เลือกเซนเซอร์ กด BOOT แล้วปล่อยเพื่อสลับ RGB0 กับ RGB1 และกด SW1 แล้วปล่อยเพื่อเข้าสู่เมนูสี ลำดับเมนูสีคือ Red, Green, Blue, Yellow, White, Black, Save all, Sensor menu และวนกลับ Red กด SW1 แล้วปล่อยที่สีเริ่มเก็บ 20 เฟรม กด SW1 แล้วปล่อยที่ Save all บันทึกทุก record ที่เก็บเสร็จ กด SW1 แล้วปล่อยที่ Sensor menu กลับไปเลือกเซนเซอร์

แต่ละปุ่มเกิดคำสั่งครั้งเดียวเมื่อปล่อยหลังสถานะนิ่ง 30 ms กดค้างไม่ทำซ้ำ ปุ่มที่ค้างตอนเข้าเมนูต้องปล่อยแล้วกดใหม่ ถ้ากดสองปุ่มซ้อนกัน จะไม่รับคำสั่งจนปล่อยทั้งคู่ ระหว่างเก็บตัวอย่างเมนูไม่รับการเปลี่ยนรายการ จอยังแสดงความคืบหน้า คำสั่ง Serial เดิมยังใช้ได้

เสียงปุ่มดังหนึ่งครั้งเมื่อเมนูรับคำสั่ง Next ใช้ 1400 Hz นาน 35 ms ส่วน Select ใช้ 2600 Hz นาน 80 ms ปุ่มที่ถูกละเลยระหว่างเก็บตัวอย่างไม่ส่งเสียง เสียง Select เป็นการตอบรับการกดเลือก ไม่ใช่การยืนยันว่าบันทึก Flash สำเร็จ ใช้ `tone()` แบบไม่รอ และหยุดพร้อมคืนทรัพยากร PIO ด้วย `noTone()` ในการอัปเดตหลังครบเวลา ขา Buzzer คือ `PUPPYBOT_BUZZER_PIN` อ้าง GPIO2 จาก `softTone()` เดิม

เมื่อ `updateRGBCalibration()` เก็บครบหนึ่งสีสำเร็จ มีเสียงสองโน้ต 2000 Hz นาน 70 ms เว้น 50 ms แล้ว 3200 Hz นาน 110 ms เกิดครั้งเดียวต่อชุดที่เก็บสำเร็จ ทั้งเมื่อเริ่มผ่าน SW1 และ Serial ไม่มีเสียงสำเร็จเมื่อยกเลิก เซนเซอร์หลุด หรือหมดเวลารอข้อมูล ทำนองไม่รอให้เสียงจบ การกดเมนูใหม่แทนที่เสียงเดิมได้ เสียงนี้ยืนยันการเก็บใน RAM การบันทึก Flash ยังต้องเลือก Save all หรือส่ง `s`

ขา SW1 อ้าง `swpin` ของ `puppybot.h` ซึ่งปัจจุบันเป็น GPIO27 ตาม `wait_SW1()` เดิม ไม่ใช้ GPIO6 ที่ปรากฏในบล็อก Blockly รุ่นเก่า เพราะขัดกับ `wait_SW1()` และ GPIO6 ใช้เป็น SDA1 ของตัวอย่างนี้ การต่อปุ่มบนหุ่นจริงยังต้องทดสอบกับบอร์ด

EEPROM ของ Arduino-Pico เป็น Flash จำลอง 4096 ไบต์ รูปแบบข้อมูลรุ่น 2 ใช้ไบต์ 3072–3399 รวม 328 ไบต์ มี magic, version, ATIME, gain, minimum Clear, 12 records และ CRC32 แบบ little-endian ไม่ใช้ native struct layout ส่วนอื่นของ sector คงค่าเดิมเมื่อ commit ชุดนี้เป็นเจ้าของการเริ่ม EEPROM ขนาด 4096 ไบต์ การใช้ EEPROM อื่นร่วมกันต้องเว้นช่วงดังกล่าวและไม่เปลี่ยนขนาด buffer

มีการเขียน Flash เมื่อเรียก `saveRGBCalibration()` เท่านั้น core Arduino-Pico 6.2.0 หยุดและปล่อยอีก core ภายใน `EEPROM.commit()` รุ่นนี้ไม่เก็บสำเนาสำรองสองชุด หากข้อมูลเสียหายจะปฏิเสธการโหลด ควรเก็บ CSV ที่ส่งออกไว้ด้วย

รุ่นนี้ใช้ 50.4 ms / Gain 4× แบบ High-PuppyBot6 ทั้งสองช่อง บันทึกการตั้งค่าลง header v2 และปฏิเสธข้อมูล v1 จาก 2.4 ms โดยไม่ลบ Flash อัตโนมัติ ต้อง Calibrate ใหม่ การเปลี่ยนแสง ระยะ หรือมุมยังต้องสอบเทียบใหม่ ดู [API แยกสีแบบ High](../RGBClassify/README.md)

เรียก updateRGB() ทุก loop1 หลังอัปเดต IMU โดย Lib ตรวจเวลาเอง ไม่มี delay รอ integration รวมถึงตอน reconnect การ Save ยังใช้ EEPROM.commit ที่หยุดอีก core ชั่วคราวตาม core Arduino-Pico เช่นเดิม จึงควร Save ตอนหยุดหุ่น

รุ่น 0.1.8-dev เก็บเฟรมที่ทำให้เกิด InvalidSignal ไว้ใน RAM อ่านผ่าน `getRGBCalibrationState().rejectedReading()` และ `rejectionMessage()` ขณะ state เป็น InvalidSignal จอแสดง FAIL แทน LIVE และค้างค่าชุดนี้จนเลือกสีหรือเริ่มเก็บใหม่ ข้อความแยกเป็น RGB zero, Clear <10 และ Saturated เกณฑ์ยอมรับและข้อมูล Flash v2 ไม่เปลี่ยน

BOOT อ่านผ่าน `BOOTSEL` ของ Arduino-Pico โดยไม่กำหนด GPIO การ begin ไม่อ่าน BOOTSEL ทันที อ่านครั้งแรกเมื่อ update เมนูและอย่างถี่สุดทุก 20 ms หยุดอ่านระหว่างเก็บสี และโหมด Show ไม่เรียกตัวอ่านปุ่มเลย การอ่าน BOOTSEL หยุดอีก core ชั่วคราว จึงอาจขัดจังหวะ IMU ระหว่างใช้เมนู ต้องยืนยันกับปุ่ม BOOT จริงบนบอร์ด ชื่อ beginRGBCalibrationSW1/updateRGBCalibrationSW1 คงไว้เพื่อให้สเก็ตช์เดิมคอมไพล์ได้ แต่ควบคุมด้วย BOOT และ SW1 ตามรูปแบบใหม่นี้
