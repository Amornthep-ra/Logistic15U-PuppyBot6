# RGB monitor — local 0.1.2-dev

ใช้กับ Library รุ่นพัฒนาในเครื่องที่มี `PuppyBotRGB.h` และ
`PuppyBotRGBDisplay.h` เปิดตัวอย่าง `RGBMonitor.ino` หรือใช้คำสั่งดังนี้:

```cpp
beginRGB();                 // เริ่มเซนเซอร์ทั้งสองบัส
updateRGB();                // อ่านทั้งสองตัวและเก็บค่า
showRGB();                  // แสดงทั้งสองตัวบน TFT
```

เรียก `puppybot_setup()` ก่อนใช้จอ ตัวอย่างแบบ core เดียวเรียกทั้งสามคำสั่งจาก
`setup()`/`loop()` ได้ ส่วนสเก็ตช์สอง core ที่ใช้อยู่ให้จัดวางดังนี้:

| ตำแหน่ง | คำสั่ง |
|---|---|
| `setup()` หลังเริ่มบอร์ด/จอ | `beginRGBDisplay();` |
| `setup1()` หลังรอ `setup()` เสร็จและเริ่ม IMU | `beginRGB();` |
| `loop1()` ทุกครั้ง | `updateRGB();` |
| `loop()` เช่นทุก 100 ms | `showRGB();` |

เลือกดูช่องเดียวด้วย `showRGB(RGB0)` หรือ `showRGB(RGB1)`
เมื่อกลับมา `showRGB()` จะเปลี่ยนเป็นหน้าสองช่อง

## อ่านค่าผ่าน API

```cpp
RGBReading color0 = readRGB(RGB0);  // อ่านอุปกรณ์ทันที จาก core ที่เป็นเจ้าของ I2C
RGBReading color1 = readRGB(RGB1);

// ใช้ค่าที่เก็บไว้จากอีก core โดยไม่อ่าน I2C เพิ่ม
RGBReading cached0 = getRGB(RGB0);
RGBSnapshot both = getRGBSnapshot();
uint16_t clear0 = getRGB(RGB0).clear;
uint16_t clear1 = getRGB(RGB1).clear;
```

- `.red`, `.green`, `.blue`: สเกลเดิม `channel / integer mean(R,G,B) * 100`
- `.rawRed`, `.rawGreen`, `.rawBlue`, `.clear`: ค่าดิบของเซนเซอร์; Clear ไม่ถูกปรับสัดส่วน
- `.colorTemperature`, `.lux`: ค่าที่ไลบรารี Adafruit คำนวณ
- `.sampled`: เคยอ่านแล้ว; `.connected`: อ่านได้/พบอุปกรณ์ในรอบนั้น
- `.sampledAt`: เวลาอ่านล่าสุดในหน่วย `millis()`

`beginRGB(RGB0)` เริ่มเฉพาะตัวแรกได้เช่นกัน การอ่านจะเริ่มอุปกรณ์อัตโนมัติเมื่อยัง
ไม่เคยเริ่ม บัสที่หายไปจะลองเริ่มใหม่ทุก 1 วินาที ส่วนบัสที่ใช้งานได้ยังอ่านต่อ
`beginRGB()` คืน `true` เมื่อเริ่มได้ทั้งสองตัว หากคืน `false` ยังใช้ช่องที่พบได้

ค่าของ RGB1 ยังคัดลอกเข้า `TCS_R/G/B/T/L` สำหรับ API เดิมด้วย
หมายเลขช่องที่ไม่ถูกต้องไม่เปลี่ยนค่า/อ่านอุปกรณ์อีกช่อง

## หน้าจอ

หน้าจอพื้นเข้ม แยก RGB0 สีฟ้าและ RGB1 สีส้ม มีตัวเลขและแถบ R/G/B พร้อมช่องสี
และค่า `C`/`Clear` แบบดิบ รองรับตัวเลข 5 หลักบนจอทั้งแนวนอน/แนวตั้งและหน้าช่องเดียว
สเก็ตช์หลักแสดงทาง Serial เป็น `RGB0(R,G,B,C)` และ `RGB1(R,G,B,C)`
ช่องสีเป็นภาพสัดส่วนสีที่อ่านได้ ไม่ใช่การจำแนกสีพัสดุที่สอบเทียบแล้ว
ตัวเลขแสดงสเกลปรับสัดส่วนตาม Library ไม่ใช่จำนวน ADC ดิบ

แสดง `Wait` ก่อนอ่าน, `Ready` เมื่อพบเซนเซอร์ และ `Offline` เมื่อไม่พบ
เคลียร์ทั้งจอเฉพาะเปิดหน้าจอครั้งแรก เปลี่ยนมุม/ขนาดจอ เปลี่ยนโหมดหนึ่ง/สองช่อง
หรือเรียก `beginRGBDisplay()` เพื่อวาดหน้าใหม่ ส่วนการอัปเดตปกติวาดเฉพาะตัวเลข
สถานะ ช่องสี หรือช่วงของแถบที่เปลี่ยน ค่าเดิมไม่ส่งคำสั่งวาดเพิ่ม

ถ้าวาดหน้าอื่นทับแล้วต้องการกลับมา ให้เรียก `beginRGBDisplay()` อีกครั้ง
อ่าน I2C (`beginRGB/readRGB/updateRGB`) จาก core เดียว และวาด TFT จาก core เดียว
`getRGB()`/`getRGBSnapshot()` ใช้ mutex เพื่ออ่านค่าข้าม core ได้ครบชุดต่อช่อง
แต่ละบัสอ่านเรียงกัน ไม่ใช่การจับภาพสองเซนเซอร์ในเวลาเดียวกัน

ขาเดิมในซอร์สคือ Wire GPIO4/5 และ Wire1 GPIO6/7 ไม่ได้วัดการต่อสายใหม่
ไม่เพิ่มค่า Encoder, มุม Servo หรือเกณฑ์จำแนกสี การแก้นี้ยังไม่เผยแพร่ GitHub

รุ่น 0.1.8-dev: beginRGB เริ่มเปิดเซนเซอร์แบบไม่รอเฟรมแรก; updateRGB/readRGB คืน cache เดิมระหว่างรอ อ่านเฟรมใหม่เมื่อครบอย่างน้อย 55 ms ไม่มี delay รอ integration ตั้งทั้งสองตัวเป็น 50.4 ms / Gain 4× ให้เรียกจาก core เดียวกับ IMU เมื่อใช้ Wire1 ร่วมกัน
